# 首页热门推荐设计

## 范围与现状

仅替换本周强推(type2，5本)及热门推荐(type3，6本)。本周强推使用近7天，热门推荐
使用近15天有效阅读时长；累计点击量只作同分排序。用户已确认15天窗口及节省资源方向。
轮播(type0，4本)、文字人工推荐(type1，10本)、精品(type4，6本)保持原后台配置；
资讯仍走独立newsList，不接推荐算法。点击/新书/更新榜不动，不做个人推荐、VIP或评分算法。
定时生成Redis快照，type2/3原后台推荐作为各自补位和故障兜底。

现有入口是 BookController.listBookSetting -> BookServiceImpl.listBookSettingVO。
接口返回 Map<String,List<BookSettingVO>>，按 type 分组。原推荐来自 book_setting，
首页初始化配置总数31，type0..4 的槽位数分别为4、10、5、6、6。
原方法缓存为空时会执行初始化并删除重建 book_setting；新请求路径不得沿用这个写库行为。
当前点击量仅有累计 visit_count，阅读日统计来自 book_reading_daily。

## 算法与资格

三种选择：实时聚合（请求成本高）、加权综合分（累计点击容易压过近期阅读，需调参）、
定时按阅读时长主排序（推荐，解释简单，利用已有日表）。采用第三种，不新增每日点击采集。

统计窗口使用Asia/Shanghai，均包含今天：7天为today-6到today，15天为today-14到today。
一次生成只读取一次Clock，使用共同的上界today+1，过滤未来日期。
用单条SQL在15天范围内按book聚合，并条件求和计算7天秒数；两组分别按对应阅读秒数
降序、COALESCE(visit_count,0)降序、book.id升序。对应窗口秒数>0才算算法候选。
使用数据库有界排名取得7天前5和15天前11候选，最多16本元数据，不把所有书籍拉进JVM排序。
15天多取5本是给排除7天榜的5本留余量，不额外扫描31个首页槽位。
通过EXPLAIN验证日期主键范围与聚合/资格查询成本；单条SQL不等于保证单次物理扫描。
累计点击只作同分排序，不宣称近7天或15天点击量。

资格：书籍存在，COALESCE(is_vip,0)=0，word_count>0，并有非VIP章节和对应DB正文。
以 EXISTS 表达章节/正文资格，避免多章节JOIN放大阅读秒数；日表先按书聚合后关联书籍。
目前没有已核实的上下架/审核字段，不把连载/完结 book_status 当成公开状态。
未来新增上下架机制时，资格判断与失效机制必须一起扩展。

先填type2最多5本，再填type3最多6本。各组热门不足时只用该组后台合资格推荐补位，
组内去重。type3优先跳过已在type2出现的书；独立候选不足时允许跨组重复以保持有内容，
但不复制同一本书凑满单组。人工type0/1/4不参与算法去重，不为了避免重复擅自换人工书。
算法及补位均不可返回VIP、孤立统计ID或没有正文的书；人工三组维持原选书语义，
不是本阶段新增审核过滤机制。热门组允许少展示，配置为空允许空组。
只生成type2/3的VO type/sort元数据，不写回book_setting；人工配置仍保持原排序。
后台type2/3调整下次刷新作为补位生效，type0/1/4下次刷新照原配置生效。
PC与移动端保留原接口/字段/布局。PC确认为type2本周强推、type3热门、type4精品；
当前移动端已有type3/type4，没有展示type2，不新增移动区块，仅让现有热门使用15天结果。

## 组件与请求路径

新增只读推荐Mapper、纯排序/分槽组装器、快照服务及定时刷新组件，避免扩张BookServiceImpl。
使用推荐专用Redis键（带格式版本），不覆盖旧首页设置缓存。
快照包含生成时间与五组最多31本完整VO，一次SET写入，不先DEL；验证版本、组内重复ID、
每组数量、分槽及时间后接受缓存，允许上述跨组重复。应用内只保留一个不可变快照，原子替换。

默认每5分钟刷新，Redis TTL15分钟；应用内最后成功快照最多使用24小时。
刷新完整查询/组装成功后才替换快照；Redis写失败仍可发布成功构建的本机快照，记录失败。
MySQL查询失败不发布空快照，不覆盖已有结果。正常查询成功但候选少/为空允许发布真实结果。
单实例部署，专用单线程调度器串行刷新，不占用阅读异步池，不创建无界异步提交队列。
启动时调度一次刷新；请求不等待聚合完成，也不在请求内触发热门日表查询。

首页请求顺序：有效Redis快照 -> 有效本机最后成功快照 -> 原后台推荐（type2/3合资格）。
冷启动兜底只做有界SELECT，不调用原初始化写库操作；以单飞和短期本机缓存防止并发重复查询。
兜底DB也失败且无快照时返回相同Map结构的空列表，不影响首页其他区块。
Redis不可用时不无限重试、不把聚合工作转移到请求线程。
本机降级快照可能暂时陈旧；本阶段没有实时下架功能，不能宣称支持即时安全撤稿。

## 安全、指标与边界

查询窗口、槽位和候选数由服务端有界配置控制，不接受前端拼接SQL排序。
推荐只使用书籍聚合指标，不读取Cookie/IP/个人身份，不影响阅读心跳闸门。
指标：刷新成功/失败（DB、Redis）、请求来源（Redis、本机、兜底、空）、快照年龄与生成耗时。
标签不包含bookId、请求身份或异常消息；日志不打印正文、Cookie或密钥。
既有累计点击/有效时长都不是不可作弊信号，不宣称此榜单彻底抵御刷量。
7/15天窗口不包含2000年故障演练数据，书籍关联也排除孤立测试ID。

## 验证与交付

TDD覆盖7/15天窗口/午夜、两组不同排序、累计点击同分排序、稳定顺序、各组后台补位、
组内去重及跨组优先去重/不足允许重复、人工三组不变、资讯/独立榜单不变、
资格过滤、槽位边界与不足、只读兜底、Redis故障、DB刷新失败保留旧快照、过期快照、
冷启动并发单飞和完整快照替换。SQL集成测试确保多章节不重复累加、未来/过旧日期不入榜。
接口/PC/移动端兼容测试核对BookSettingVO字段与分组，配置合约与监控同步补齐。
本地验收使用隔离数据或只读检查，不更新真实book_setting，不清空日表/Redis。
全量回归后由用户提交；继续当前feature/chapter-performance工作树，不合并分支。
不修改三份用户已有配置：novel-admin application-dev/prod及novel-common application-common-dev。
